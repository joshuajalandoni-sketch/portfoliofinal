# CLAUDE.md

Standing instructions for Claude Code working in this repository.

---

## What this project is

A personal portfolio site for **Joshua Jalandoni**, a freelance web designer and developer
based in Bacolod City, Philippines. Static HTML, CSS, and JavaScript. No build step, no
framework. Deployed on Vercel.

The site's purpose is to convince small business owners that Joshua is a safe, capable hire.
Every decision should serve that.

---

## Read first

Before starting any task, read **`DESIGN.md`**. It is the source of truth for typography,
color, spacing, section structure, and motion. If a request conflicts with `DESIGN.md`, say
so before proceeding rather than silently picking one.

---

## How to work here

**Ask before large changes.** If a task will touch more than three files or rewrite an
existing section, describe the plan first and wait for approval.

**Never invent content.** If a section needs copy, a client name, a date, a testimonial, or a
statistic that isn't in the repo, stop and ask. Placeholder text like "Lorem ipsum,"
"Client Name," or a made-up metric must never reach the codebase. An empty section is better
than a fabricated one.

**Point out problems.** If a request would break the design system, hurt accessibility, hurt
performance, or damage how the site reads to a non-technical business owner, say so plainly
before doing it. Do the work if Joshua still wants it, but flag the issue first — don't stay
quiet to be agreeable.

**Explain in plain language.** Joshua builds sites but does not have a deep framework or
tooling background. Skip jargon, or define it in one clause when it's necessary.

**Verify, don't assume.** Read the actual file before editing it. Don't assume a class,
variable, or path exists because it would be reasonable for it to exist.

---

## Hard rules

1. **Never hardcode a color, font size, spacing value, or radius.** Everything comes from the
   CSS custom properties defined in `DESIGN.md`. If a token is missing, propose adding it.
2. **Every new section must work in both light and dark mode.** The theme toggle already
   exists; test both.
3. **Never modify `.gitignore` or `.vercelignore`.**
4. **Never delete files.** Move them to `_archive/` instead.
5. **Never commit or push** unless explicitly asked. Show the diff instead.
6. **Don't convert this to a framework.** No React, no Next.js, no build step, no bundler,
   unless explicitly requested. It's a static site and that is deliberate.
7. **Don't add dependencies** without asking. Fonts and icons come from a CDN; nothing else
   gets added casually.
8. **Never publish anything from Joshua's contract work.** No client screenshots, account
   data, funnel data, or internal tooling — for any employer or client. Describe work in
   words only.

## File and asset conventions

Structure:

```
/
├── index.html
├── DESIGN.md
├── CLAUDE.md
├── README.md
├── ASSETS.md
├── public/
│   ├── images/
│   │   ├── hero/
│   │   ├── projects/
│   │   ├── certifications/
│   │   ├── clients/
│   │   └── og-image.jpg
│   ├── files/
│   └── favicon.ico          TODO: not created yet (inline SVG favicon in use)
├── _source/
└── _archive/
```

Filenames: lowercase, hyphens only. No spaces, no underscores, no dates, no UUIDs, no `(1)`
suffixes. The name should say what the file is without opening it. Keep the file's real
extension: renaming does not convert a file, so a WebP stays `.webp`.

- Projects: `{project-slug}-{desktop|mobile}.{ext}`
- Certificates: `{issuer}-{course-name}.{ext}`
- Clients: `{client-slug}.{ext}`

After moving or renaming any asset, update every reference to it and update `ASSETS.md`.

## Content data

Project, certification, and experience data belongs in a single JS data array, with the
markup generated by one template function per type. Do not hand-write twelve certificate
cards in HTML — a future edit would then mean twelve edits.

---

## Definition of done

A section isn't finished until all of these are true:

- Works at 360, 768, 1024, and 1440 wide
- Works in light and dark mode
- Keyboard focus is visible on every interactive element
- Images have alt text and explicit dimensions
- No hardcoded design values
- `prefers-reduced-motion` respected if it animates
- No console errors

## Working mode

Default: measure, then build, in one turn. Do not stop for
approval. Report after, under 150 words, numbers not prose.

Verify dark only at 360 and 1440 unless the change is
layout-structural. Before/after screenshot at 1440.

If you measure something that contradicts my spec, say so and
build your version. Show the numbers.

Stop and ask ONLY for:
- deleting or rewriting content in CONTENT.md
- changes touching more than one section
- anything in vercel.json, build config, or repo structure
- anything involving LSF, client names, or contract work
